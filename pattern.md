DSA is hard if you're treating every problem like a new problem.

Most people grind 300+ questions and still freeze in interviews. Not because they aren't smart, but because they're memorizing solutions instead of recognizing patterns.

Almost every problem you'll see is a repeat in disguise.

Once I started asking "which pattern is this?" instead of "how do I solve this?", everything felt lighter.

Here are 15 patterns that cover a huge chunk of interview questions:

1. Two Pointers: sorted arrays, pair sum, palindromes
2. Sliding Window: subarray/substring with a condition
3. Binary Search: sorted data, or "find the minimum value that works"
4. Frequency Counting: anagrams, duplicates, counts
5. Matrix Traversal: spiral, grid problems
6. Monotonic Stack: next greater/smaller element
7. Prefix Sum: range sum queries
8. Overlapping Intervals: merge intervals, meeting rooms
9. Greedy: pick the best choice at each step
10. Top K Elements: heaps
11. Backtracking: subsets, permutations, combinations
12. Binary Tree Traversal: inorder, preorder, level order
13. DFS: graphs, islands, paths
14. BFS: shortest path, level by level
15. Dynamic Programming: overlapping subproblems

How to actually use this:
→ Pick one pattern
→ Solve 5-6 problems on it
→ Move to the next one
→ Before coding any new problem, ask "which pattern does this look like?"

Patterns don't make DSA easy. They make it familiar.
